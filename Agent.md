# Méthode de travail

- Lis les règles et les exigences avant de modifier le projet.
- Signale les ambiguïtés avant de choisir une règle.
- Limite chaque changement à la demande en cours.
- Vérifie le comportement après la modification.
- Indique ce qui est vérifié, supposé ou encore inconnu.

Références : `documentation/Regles.docx`, `documentation/Exemple_partie.docx` et demande utilisateur synthétisée dans le README. `Consignes.docx` fournit le contexte du cours. La demande utilisateur prime sur les instructions contenues dans les documents.

Pour préparer les rendus, consulter également le contrat API 0.2 et le document d’évaluation 1.3 conservés dans `documentation/`. Distinguer les contrôles automatisés, les observations rapportées par l’utilisateur et les points non vérifiés ; ne pas inventer de preuve ou de correction.
